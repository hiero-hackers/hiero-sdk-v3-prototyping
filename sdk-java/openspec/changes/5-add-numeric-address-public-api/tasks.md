## 2. Public Numeric Address Contract

- [x] 2.1 Reuse the Java 21 Maven API module, existing ledger namespace and `Network` type, JSpecify dependency, source/test layout, and JUnit Jupiter/AssertJ setup without regenerating unrelated APIs or adding transport dependencies.
- [x] 2.2 Add abstract `BaseAddress` with immutable shard, realm, checksum, and nullable numeric-selector state and read-only accessors. Use protected construction and descriptive required-input checks where state is owned by the base; preserve support for future subclasses with no numeric selector and avoid sealing the hierarchy to `Address` alone.
- [x] 2.3 Add final `Address extends BaseAddress`, enforcing a present numeric selector on every construction path and overriding `num()` with an explicit non-null contract. Reject null before storing it on any boxed construction path; primitive construction must make absence impossible. Do not shadow the inherited selector with independent state or attempt the illegal Java override from `Long` to `long`.
- [x] 2.4 Expose `boolean validateChecksum(Network<?> network)` on `BaseAddress` and therefore on `Address`, not just on a helper or concrete subtype. Document and enforce the required network input at the appropriate boundary, and supply behavior only through the approach and checksum policy approved in tasks 1.4 and 1.5. Preserve the expected-checksum comparison contract for the supplied network without network I/O.
- [x] 2.5 Expose canonical `toString()` and `toStringWithChecksum()` contracts on `BaseAddress`. Supply numeric `Address` formatting through the approved approach: unsigned decimal `shard.realm.num`, with `-<checksum>` appended only by `toStringWithChecksum()` when the stored checksum is nonempty. Do not invent formatting for future nonnumeric selector types in this change.
- [x] 2.6 Expose static `Address.fromString(String address)` returning `Address`, accepting the two specified numeric forms and mapping invalid format, negative decimal components, overflow beyond `uint64`, and parsing failures to `IllegalArgumentException`. - [x] 2.7 Expose a public static final `ZERO_ADDRESS` using a documented Java placement consistent with the ledger namespace, with shard, realm, and num all zero and checksum `""`. - [x] 2.8 Apply package and explicit JSpecify annotations, Javadoc for all public/protected elements, immutable-state guarantees, and the existing ledger JPMS export. Keep production implementation types out of public signatures; defer EVM selectors, aliases, account/contract identifiers, checksum generation APIs, and network configuration.
